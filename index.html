Timing attack on a password check

A server checks a password one character at a time and stops at the first mismatch. A wrong guess whose first 3 characters are correct takes a little longer to reject than one that is wrong at the first character. An attacker who can measure that difference recovers the secret one character at a time.

Things to try

  • Set noise to 40 with 1 sample. The attacker starts guessing wrong. Raise the sample count and watch averaging cancel the noise. Real attackers do the same thing.
  • Switch to constant-time compare. Every bar is the same height apart from noise, so the attacker learns nothing.
  • Make the secret longer. Brute force grows exponentially and the timing attack only linearly.

Reading a secret exponent from a power trace

RSA decryption computes cd mod N with square-and-multiply. Exponentiation takes O(log d) operations this way instead of O(d), which is what makes RSA practical. But the algorithm only multiplies when a key bit is 1. A multiply draws a different amount of power than a square, so an oscilloscope on the chip shows the private key bit by bit.

S = square (short, lower power) M = multiply (long, higher power)

Why a side channel changes the complexity class

Security often rests on a search space too big to explore: kn passwords for alphabet size k and length n. A side channel that confirms one character at a time splits that search into n independent searches of size k, which makes it linear instead of exponential. Adding a character multiplies brute-force work by k but adds only k × samples guesses to the attack.
